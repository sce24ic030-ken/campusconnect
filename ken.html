Project overview (from scratch)

What CampusConnect is and why it exists

In one sentence

CampusConnect is a web-based “AI College Companion” that brings a student's entire campus life into one secure login — academics, attendance, timetable, exams, results, assignments, events, placements, faculty, complaints, lost & found, documents, notifications and feedback — all powered by a Flask REST API over a MySQL database.

The problem

Students juggle notice boards, portals, WhatsApp groups and paper records. Information is scattered and easy to miss, and there is no single place to act on it.

The solution

One integrated portal with a single login. Every module is data-driven from a central MySQL database and exposed through clean JSON endpoints the frontend consumes.

Objectives (as stated in the synopsis)

  • Provide a single login for all campus features and personal academic data.
  • Digitise records — courses, attendance, timetable, exams, results, assignments.
  • Keep students informed in real time via notifications, events and placements.
  • Let students act — submit assignments, raise complaints, post lost & found, give feedback.
  • Expose a clean, secure REST API with proper status codes and password hashing.
  • Lay the foundation for an AI chatbot that answers questions from the campus database.

Architecture

How the pieces fit together

CampusConnect is deliberately split into three tiers. The backend is a pure JSON API — it has no server-rendered templates — and the frontend is a separate static site that calls it over HTTP.

  ┌──────────────────────────────────────────────┐
  │  FRONTEND  (static HTML / CSS / JS)          │
  │  index.html · register.html · dashboard.html │
  │  pages/*.html  (academics, exams, …)         │
  │  calls the API with  fetch() + Bearer JWT    │
  └───────────────┬──────────────────────────────┘
                  │  HTTP  /api/...
                  ▼
  ┌──────────────────────────────────────────────┐
  │  FLASK BACKEND  (create_app factory)         │
  │                                              │
  │  routes/     22 blueprints  (controllers)    │
  │  services/   chatbot · notification · reminder│
  │  models/     courses data-access             │
  │  utils/      security · helpers · validators │
  │  config.py   env-driven configuration        │
  └───────────────┬──────────────────────────────┘
                  │  mysql-connector-python (raw SQL)
                  ▼
  ┌──────────────────────────────────────────────┐
  │  MySQL 8  —  database "campusconnect"        │
  │  18 tables, foreign keys, ON DELETE CASCADE  │
  └──────────────────────────────────────────────┘

Request lifecycle

1 · Client requestBrowser sends fetch("/api/attendance") with an Authorization: Bearer <token> header.
2 · CORS + JSON providerFlask-CORS allows the origin; the custom JSON provider handles dates, times and Decimals.
3 · Blueprint routeThe matching blueprint handler runs; @token_required verifies the JWT and injects request.user_id / role.
4 · Raw SQLdatabase/db.py opens a connection and runs query_all / query_one / execute with parameterised SQL.
5 · Envelope responseRoute returns {"success":true,"data":…} or {"success":false,"message":…} with an HTTP status code.

Backend walkthrough

Layer by layer, top to bottom

Application factory — app.py

The entry point builds the app inside create_app() instead of at import time — the standard Flask pattern that makes testing and deployment easier. It loads config, installs a custom JSON provider, wires CORS, registers 22 blueprints and adds JSON error handlers.

# app.py — core of the factory
class CampusJSONProvider(DefaultJSONProvider):
    def default(self, obj):
        if isinstance(obj, (datetime, date, time)): return obj.isoformat()
        if isinstance(obj, timedelta): return str(obj)
        if isinstance(obj, Decimal):   return float(obj)
        return super().default(obj)

def create_app():
    app = Flask(__name__)
    app.config.from_object(get_config())
    app.json = CampusJSONProvider(app)          # dates/Decimals → JSON
    CORS(app, origins=...)                       # from config
    for bp in blueprints: app.register_blueprint(bp)
    ...
    return app

app = create_app()

Configuration — config.py

Previously an empty file. Now it reads everything from environment variables via python-dotenv, exposes a get_config() that returns the right class for dev/prod, and never hard-codes secrets.

Database helpers — database/db.py

Originally only had create_database() and get_connection(). Three thin wrappers were added so route files stay short and consistent, and every call is parameterised (no string-concatenated SQL → no SQL injection):

HelperPurpose
query_all(sql, params)Run a SELECT → list of dicts.
query_one(sql, params)Run a SELECT → one dict or None.
execute(sql, params, return_id)INSERT/UPDATE/DELETE with commit + rollback on error; returns new id or row count.

Routes — routes/

One blueprint per feature area. Each file defines a Blueprint with its own url_prefix (e.g. /api/attendance), guards handlers with @token_required / @admin_required, validates input, runs SQL, and returns the standard JSON envelope.

Models, services, utils

FolderContents
models/courses.py rewritten from a broken SQLAlchemy leftover into a small raw-SQL data-access layer (get_all_courses, get_course_by_id).
services/chatbot_service.py (NVIDIA NIM call + rule-based fallback), notification_service.py, reminder_service.py.
utils/security.py (JWT create/verify + decorators), helpers.py (success()/error()), validators.py (date/time/int checks).

Deployment files

wsgi.py exposes the app for production servers, Procfile contains the gunicorn start command, and .env.example documents every required environment variable.

Authentication & security

JWT, hashing and role guards

How a login works

POST /api/auth/registerCreates the account; the password is hashed with PBKDF2 — the plain text is never stored. New users get role student.
POST /api/auth/loginVerifies the hash and returns a signed JWT plus the user object.
Protected requestsClient sends Authorization: Bearer <token>; the decorator decodes it and injects user_id / role.

Guards — utils/security.py

DecoratorEffect
@token_requiredValid JWT required; sets request.user_id and request.user_role.
@admin_requiredAlso requires role = 'admin'.

Tokens are signed with JWT_SECRET and expire after JWT_EXPIRY_HOURS (default 24). Promote a user to admin directly in MySQL:

UPDATE campusconnect.users
  SET role = 'admin'
  WHERE email = 'you@example.com';
Security checklist: parameterised SQL everywhere · PBKDF2 password hashing · secrets only in .env (git-ignored) · student data scoped by JWT user_id, never by request body · admin-only routes guarded · consistent HTTP status codes (400/401/403/404/405/500).

The AI chatbot

LLM-first, always answers

The chatbot is the “AI” in AI College Companion. It tries a real LLM first and degrades gracefully so the endpoint never fails.

1 · Try the LLMPosts to NVIDIA NIM (integrate.api.nvidia.com/v1) using openai/gpt-oss-20b, feeding the model the student's live attendance, assignments, exams and timetable so it can guide them in-app.
2 · ReplyReturns the answer in data.reply with data.intent = "llm".
3 · FallbackIf NVIDIA_API_KEY is unset, or the model errors/times out, a built-in rule-based assistant answers instead — so /api/chatbot/message always responds.

Relevant config keys: NVIDIA_API_KEY, CHATBOT_MODEL, CHATBOT_TIMEOUT, CHATBOT_REASONING_EFFORT. In the original snapshot this was an empty placeholder file.

Setup from scratch

Get it running on a clean machine (Windows / PowerShell)

Prerequisites: Python 3.12+, MySQL 8 running on localhost:3306.

# 1 — go to the backend
cd "C:\Users\acube\OneDrive\Desktop\Rahul\BCA\backend"

# 2 — create and activate a virtual environment
python -m venv .venv
.\.venv\Scripts\Activate.ps1

# 3 — install dependencies
pip install -r requirements.txt

# 4 — create your .env and fill in your MySQL password
Copy-Item .env.example .env
notepad .env

# 5 — create the database + tables
python setup_schema.py

# 6 — run the API
python app.py

The API is then available at http://127.0.0.1:5000. Open the frontend pages directly in a browser (or serve the frontend/ folder) and they will call that API.

Deployment

Shipping it to a real host

PythonAnywhere (free tier)

  • Upload / clone the backend folder.
  • Create a virtualenv and pip install -r requirements.txt.
  • Add a MySQL database, put its values in .env, run python setup_schema.py.
  • Manual config → Flask; point the WSGI file at wsgi.py / app.application.
  • Reload the web app.

Render / other hosts

  • Build: pip install -r requirements.txt
  • Start: gunicorn app:app (already in the Procfile).
  • Use a managed MySQL (e.g. Aiven free) and set the DB env vars in the host dashboard.
In production set FLASK_ENV=production, FLASK_DEBUG=False and strong SECRET_KEY / JWT_SECRET values.

Glossary

Plain-English terms used above

TermMeaning
REST APIA way for programs to talk over HTTP using URLs, verbs (GET/POST/PUT/DELETE) and JSON.
BlueprintFlask's way to group related routes (e.g. all attendance endpoints) into one module.
App factoryA function that builds the Flask app on demand — easier to test and deploy.
JWTJSON Web Token — a signed string the client sends to prove who it is, without server sessions.
PBKDF2A slow password-hashing function — makes stolen hashes hard to crack.
Raw SQLWriting SQL statements directly instead of using an ORM mapping layer.
CORSBrowser rule that a server must explicitly allow another origin to call it.
WSGIThe standard interface between Python web apps and production servers.
E2E testEnd-to-end test — exercises the whole system as a real user would.
